Этот файл — всё, что нужно ИИ-помощнику (Claude, ChatGPT, Cursor, Copilot и т. п.), чтобы сразу продолжить работу.

## 1. Кто владелец и что это

- Владелец — писательница **Лана Фрейтаг** (псевдоним; в настройках `settings.pseudonym`). Пишет любовные романы,
  выкладывает их главами на **Литнете** (основная площадка), а также на Литгороде, Литмаркете, Литресе.
- Два личных веб-приложения (PWA, работают в браузере на телефоне и компьютере, ставятся значком на экран):
  - **«Доходы»** — https://erichthoxx-sketch.github.io/mine/ — доход по дням и книгам из выгрузки Литнета,
    реклама и её окупаемость, программа «Литнет платит», Rocket, налог (НПД), цели по месяцам и «большая цель».
  - **«Мастерская»** — https://erichthoxx-sketch.github.io/mine/workshop/ — книги из Google Документов
    (знаки, главы, редактор глав), планер, цели письма, идеи, маркетинг, конкурсы, связи, Todoist.
  - **«Директ»** — https://erichthoxx-sketch.github.io/mine/direct/ — реклама книг в Яндекс Директе: расход, клики,
    поисковые запросы, минус-фразы, ставки, пауза; учебник; ИИ-помощник (пакет данных для любой нейросети и разбор её плана).
    Отдельное приложение: кнопки перехода в верхней панели нет, вход в него — строкой «Яндекс Директ» в карточке «Мой таргет» (вкладка «Реклама» «Доходов») и из «Мастерской»:
    Маркетинг → блок «Реклама» (Яндекс Директ и «Реклама в „Доходах“», `.mk-go`).
- **Сайт автора** — **https://lanafreitag.ru** (админка — /admin/; домен куплен в Рег.ру). Код — здесь, в `site/`; публикует его
  отдельное хранилище **erichthoxx-sketch/lanafreitag** (workflow «Публикация lanafreitag.ru» берёт `site/` из этой ветки и кладёт
  в ветку gh-pages с CNAME). **После каждой правки `site/` и push сюда — запустить тот workflow вручную** (actions_run_trigger,
  run_workflow, workflow `publish.yml`, ref `main`); сам он запускается раз в 6 часов. Старая копия — https://erichthoxx-sketch.github.io/mine/site/.
  Публичная витрина для читателей,
  **как сайт хорошего издательства**: бумага и графит, умеренная типографика (заголовки 28–58 px), плотные разделы с тонкими линиями,
  без градиентов. Акценты палитры (по умолчанию `fog`) — только подложки обложек, метки, линии. Характер дают обложки
  (цикл «С кем я, черт возьми, связалась»: криминал, медведи, похоронный бизнес). Владелица отвергла: нежный розово-голубой,
  тёмный нуар с красным, огромный шрифт, «туман»-градиенты и пустые места, большую арку вместо фото (теперь — небольшое круглое),
  блок «Герои» на странице книги. С приложениями не связан, своя админка (книги ставит туда сама, не из «Мастерской»).
  Сайт рассчитан на много книг и циклов (владелица: «цикл будет больше»): у книги поля `series` + `seriesNo`, блок «Цикл»
  сам собирает книги цикла по номеру, «Все книги» — с фильтром по циклам и появляется, только когда есть книги вне показанных циклов.

  как карточка книги у издательства: слева обложка, справа цикл и номер, название, автор, крючок (`tagline`), характеристики,

## 3. Жёсткие правила

1. **Ничего секретного в код и в репозиторий.** Ключ Todoist, пароли, токены вводятся только в самом приложении
   (Настройки) и хранятся в её данных Firebase. Если владелица прислала ключ в чат — не вставлять его никуда в код.
2. **Ветка:** вся работа и публикация — в ветке `claude/author-income-ads-tracker-3zjbxd`
   (с неё же публикуется сайт, см. раздел 5). Не создавать pull request без просьбы.
3. В текстах коммитов, коде и комментариях — **не указывать названия/версии моделей ИИ**.
4. Перед каждой публикацией: `npm test` + проверка синтаксиса изменённых файлов (`node --check файл.js`)
   + открыть приложение в браузере и убедиться, что нет ошибок. Однажды сломанный шаблон (лишняя `` ` ``)
   положил всю «Мастерскую» — не повторять.
5. Русский язык в интерфейсе: правильная грамматика, падежи («к январю 2030», «до января»), заглавная буква
   в начале фраз и кнопок («Все», «Новая глава»), неразрывные пробелы в числах (делает `tidyNums`).
6. Объём текста — **в знаках** (как на Литнете) и в авторских листах (1 а.л. = 40 000 знаков с пробелами).
   Объём книги = только то, что идёт в рукопись: вкладки «Пролог», «Глава …», «Эпилог» (без «От автора», промтов,
   каркаса, черновиков; `charsFromDocsJson`, правило `COUNT_RULE` = 4). Документ из одной вкладки — целиком.
7. В **скачиваемых файлах** (Word, PDF, архивы, имена файлов) — **без буквы «ё»**: «объём» → «объем»
   (`noYo` в `publish.js`, `download` в `ui.js`). В интерфейсе приложения «ё» можно.

### Как устроены экраны (паттерн во всём коде)

- Вид — функция `view(app) → { html, after? }`. HTML собирается строками-шаблонами; **всегда `esc()`** для
  пользовательского текста.
- Действия — через атрибуты: `data-act="имя"` → `acts['имя'](dataset, el, e)`; `data-chg="имя"` → `changes['имя'](value, el)`;
  формы `data-form` → `forms`. Вернуть `false` из действия — не перерисовывать.
- Окна: `openSheet(заголовок, html, onSubmit|null, { submitText })`. Подтверждение: `await ask(текст, кнопка)`.
- Уведомления: `toast(текст, { undo })` — с кнопкой «Вернуть».
- Данные: `app.ctx()` (вычисленный контекст: today, settings, data, книги…), запись — `app.store.put/putMany/remove`,
  настройки — `app.store.saveSettings(patch)`. После записи всё перерисовывается само (подписка).
- Скачивание файлов: `download(имя, данные, mime)` — имена файлов автоматически с `_` вместо дефисов и пробелов.
- Место в приложении (вкладка, раскрытые блоки) сохраняется в адресе (`keepPlace`) — обновление страницы не сбрасывает на главную.

- **Идеи и заметки** (`writer/js/views/ideas.js`, чистые функции — `writer/js/ideacalc.js`, тест `tests/ideas.test.js`): статусов два —
  «Открытые» и «Готово» (галочка у записи, с «Вернуть»; в базе `status` new|used, `doneAt`; старые work → открытые, archive → готово).
  Удалённые — «Корзина», через 30 дней стираются сами. Само раскладывается: книга по словам в тексте (`bookGuess`), вид — правка/сцена/
  персонаж/название/идея (`ideaKind`, можно поменять), глава («в 5 главе» → ссылка в редактор, `chapterRef`). Навигация рассчитана на тысячи книг и записей:
  поиск по всему; вкладки «Открытые | Готово | Корзина»; книга — колонкой слева на компьютере (с поиском, свежие сверху)

  задача-идея без раздела книги получает книгу по тексту и сама переезжает в её раздел.

  `refreshOne` выравнивает название главы в Документе — `baseText` берётся заново из Документа, иначе следующее автосохранение видело «правку в Документе».

## 9. Как работать над задачей

1. Понять просьбу по скриншоту/тексту; найти место в коде (`grep` по русскому тексту с экрана — быстрее всего).
2. Сделать минимальную аккуратную правку в стиле соседнего кода (комментарии — по-русски, коротко).
3. Если меняется расчёт — добавить/обновить тест в `tests/`.
4. `npm test`, `node --check` изменённых файлов, проверка в браузере (телефон 390 px и компьютер, без ошибок в консоли).
5. Коммит с понятным русским описанием → push в рабочую ветку → коротко ответить владелице, что поменялось и где смотреть.

## 11. Единый коннектор для книг, маркетинга, доходов и рекламы

- Отдельный Cloudflare Worker, не совмещать с «Директом»: proxy/books-mcp-worker.js, инструкция docs/SETUP-BOOKS-MCP.md. Развёртывание отдельное, исходники в GitHub сами в Worker не устанавливаются. Требуются BOOKS (Workers KV), OWNER_UID (Firebase uid владельца), MCP_READ_KEY (секрет в Cloudflare, не в GitHub).
- В настройках Мастерской единая кнопка «Подключить весь контекст» — writer/js/views/aicenter.js. Контекст маркетинга, доходов и сохранённого Директа собирается writer/js/ai-system.js, без токенов, паролей и личных контактов. В карточке книги «Для нейросети» — writer/js/views/bookai.js; снимок собирается в writer/js/bookai.js. «Скачать контекст» всегда доступен; «Подключить книгу» читает Google Документ + утверждённую Легенду и только по явному нажатию передаёт в личный Worker. Не выкладывать книги автоматически: полная передача, включая агрегаты финансов, выполняется только по явному нажатию и первому подтверждению владелицы в настройках. Изменения Google Docs и статистики требуют «Обновить весь контекст».
- Синхронизация в Cloudflare только для владельца: авторизация Firebase ID token, проверка RSA подписи и uid; нейросетям только чтение по X-Master-Key. Добавление записи или редактирование из MCP запрещены; всякая новая операция записи требует явного решения владелицы.
- Не размещать рукописи в git. Подключённые снимки только в закрытом Cloudflare KV. «Отключить всё» удаляет копии книг и трёх разделов из KV, «Обновить весь контекст» удаляет устаревшие книги (учитывать eventual consistency). Тесты сервера: tests/books-mcp.test.js.
- **Директ вживую** (08.11.2026, владелица: «сделай так, чтобы ты всё видела и могла подключаться по требованию»): инструмент MCP `get_direct_live`
  (`directLive` в proxy/books-mcp-worker.js) читает Директ прямо сейчас — кампании с черновиками, группы (регионы, минус-фразы), объявления, фразы,
  параметры URL, расход за 30 дней. Только методы get и отчёты (`DIRECT_READ`), ключ Директа в ответах не появляется. Ключ передаётся сам, без кнопок и вопросов
  (владелица разрешила в чате и не хочет ничего нажимать): при открытии «Мастерской» и «Директа» (`autoDirectAccess`), после нового входа в Директ; удаляется при
  «Отключить Директ»; выключено только после «Отключить всё» (`settings.aiDirectLive === 'off'`) (`js/aidirect.js`); KV `secret:direct-access`, «Отключить всё» удаляет и его. Инструментов записи в Директ у нейросети нет — не добавлять без её решения.
- Перед публикацией проверять npm test, что действующий Worker «Директа» и proxy/direct-worker.js не изменились. Коннектор в Claude требует отдельной ручной настройки URL и заголовка на стороне пользователя; ничего не обещать о полностью автоматической привязке к ChatGPT/Claude.
