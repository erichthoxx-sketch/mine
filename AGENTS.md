# Инструкция для нейросетей: приложения «Доходы» и «Мастерская»

Этот файл — всё, что нужно ИИ-помощнику (Claude, ChatGPT, Cursor, Copilot и т. п.), чтобы сразу продолжить работу.
Прочитай его целиком перед первой правкой. Если что-то в коде расходится с этим файлом — верь коду и поправь файл.

---

## 1. Кто владелец и что это

- Владелец — писательница **Лана Фрейтаг** (псевдоним; в настройках `settings.pseudonym`). Пишет любовные романы,
  выкладывает их главами на **Литнете** (основная площадка), а также на Литгороде, Литмаркете, Литресе.
- Два личных веб-приложения (PWA, работают в браузере на телефоне и компьютере, ставятся значком на экран):
  - **«Доходы»** — https://erichthoxx-sketch.github.io/mine/ — доход по дням и книгам из выгрузки Литнета,
    реклама и её окупаемость, программа «Литнет платит», Rocket, налог (НПД), цели по месяцам и «большая цель».
  - **«Мастерская»** — https://erichthoxx-sketch.github.io/mine/pisatel/ — книги из Google Документов
    (знаки, главы, редактор глав), планер, цели письма, идеи, маркетинг, конкурсы, связи, Todoist.
- Обе работают с **одними данными** одного пользователя (Firebase), настройки общие.

## 2. Как общаться с владелицей (важно)

- Только **по-русски**, просто, без программистских слов. Она не программист.
- Короткие ответы: что сделано, где посмотреть, что нажать. Без длинных отчётов о коде.
- Всё должно работать **само**: автоматически, «по полочкам», с напоминаниями в нужные даты.
  Не просить её вручную делать то, что может сделать приложение.
- Если она прислала скриншот с «криво/не так» — исправить именно это, проверить в браузере, ответить коротко.
- Если просит «сделать как дизайнер» — минимализм, гармония, единообразие (см. раздел 7).
- Нельзя выдумывать условия конкурсов, налоговые правила и т. п. Если не уверен — так и сказать.

## 3. Жёсткие правила

1. **Ничего секретного в код и в репозиторий.** Ключ Todoist, пароли, токены вводятся только в самом приложении
   (Настройки) и хранятся в её данных Firebase. Если владелица прислала ключ в чат — не вставлять его никуда в код.
2. **Ветка:** вся работа и публикация — в ветке `claude/author-income-ads-tracker-3zjbxd`
   (с неё же публикуется сайт, см. раздел 5). Не создавать pull request без просьбы.
3. В текстах коммитов, коде и комментариях — **не указывать названия/версии моделей ИИ**.
4. Перед каждой публикацией: `npm test` + проверка синтаксиса изменённых файлов (`node --check файл.js`)
   + открыть приложение в браузере и убедиться, что нет ошибок. Однажды сломанный шаблон (лишняя `` ` ``)
   положил всю «Мастерскую» — не повторять.
5. Русский язык в интерфейсе: правильная грамматика, падежи («к январю 2030», «до января»), заглавная буква
   в начале фраз и кнопок («Все», «Новая глава»), неразрывные пробелы в числах (делает `tidyNums`).
6. Объём текста — **в знаках** (как на Литнете) и в авторских листах (1 а.л. = 40 000 знаков с пробелами).
7. Личные выгрузки (`Statistic*.csv`, `dohody*.csv`, `backup-*.json`) не класть в репозиторий.

### Как устроены экраны (паттерн во всём коде)

- Вид — функция `view(app) → { html, after? }`. HTML собирается строками-шаблонами; **всегда `esc()`** для
  пользовательского текста.
- Действия — через атрибуты: `data-act="имя"` → `acts['имя'](dataset, el, e)`; `data-chg="имя"` → `changes['имя'](value, el)`;
  формы `data-form` → `forms`. Вернуть `false` из действия — не перерисовывать.
- Окна: `openSheet(заголовок, html, onSubmit|null, { submitText })`. Подтверждение: `await ask(текст, кнопка)`.
- Уведомления: `toast(текст, { undo })` — с кнопкой «Вернуть».
- Данные: `app.ctx()` (вычисленный контекст: today, settings, data, книги…), запись — `app.store.put/putMany/remove`,
  настройки — `app.store.saveSettings(patch)`. После записи всё перерисовывается само (подписка).
- Скачивание файлов: `download(имя, данные, mime)` — имена файлов автоматически с `_` вместо дефисов и пробелов.
- Место в приложении (вкладка, раскрытые блоки) сохраняется в адресе (`keepPlace`) — обновление страницы не сбрасывает на главную.

### Данные (Firebase: users/{uid}/…)

- `settings` (общие): pseudonym, taxRate (4), taxBase (gross/royalty), npdLimit, npdOther, litnetThreshold, litnetPct,
  rocketCap, widgetStep, widgetPerRub, goalStart/goalAmount/goalGrowth/goalMonths, planOverrides (свои цели по месяцам),
  planPath (путь большой цели по месяцам, в роялти), bigGoal {amount, by, kind, after: usn|ausn, startMonth, startRoy},
  todoistToken, todoist {map, closed, own, at}, папки Диска и т. п.
- «Доходы»: `sales` (продажи по дням), `books`, `days` (события дня), `campaigns` (реклама), `reports`, `months`, `adnotes`.
- «Мастерская»: `w_books` (книга: fileId Документа, tabs [{title, chars, counted, lead}], history {дата: знаки},
  pub {глава: {площадка: {date, planned}}}, publishStart, pubDays, planChapters, status idea|progress|done, platforms,
  cover, promo, synopsis), `w_ideas` (text, bookId, tags, status, tdId), `w_contests` (см. ниже), `w_goals`
  (type finish|daily|custom, perDay, days [дни недели], deadline, moved {откуда: куда}, checks), `w_queue` (что пишу дальше),
  `w_waiting` (жду ответа), `w_links` (контакты), `w_media`.
- Конкурс `w_contests`: name, platform, url, conditions (текст условий), start, end, results, genres, emails,
  unit (chars|al), minChars, maxChars, startChars, volNote, fileTpl (имя файла по условиям), chapters (первые N глав),
  formats, newOnly («пишу книгу на конкурс — подаётся законченная»), newSince, bookIds, joinedBooks {книга: дата},
  sentBooks {книга: дата}, status plan|in|sent|done, pv (версия разбора условий).

## 5. Публикация сайта

- Push в ветку `claude/author-income-ads-tracker-3zjbxd` (или main) → GitHub Actions (`pages.yml`): `npm test` →
  копирует файлы в папку версии `_site/vXXXXXXXX/` → GitHub Pages. Через 1–2 минуты сайт обновлён.
- Каждая версия в своей папке, поэтому браузер не держит старые файлы. Открытая старая вкладка сама перезагрузится
  (`window.__stale` в index.html). Библиотеки дополнительно лежат постоянной копией в `/vendor/`.
- Локальная проверка: `python3 -m http.server 8765` в корне → http://localhost:8765/ и http://localhost:8765/writer/
  (на localhost пробный режим — данные только в браузере). Для автопроверок удобен Playwright (Chromium).

## 6. Внешние сервисы

- **Firebase** (проект `dohody`): вход по почте, Firestore. Правила — `firestore.rules` (каждый видит только свои данные).
- **Google Диск/Документы** (Мастерская): книги — Google Документы с **вкладками**: «Пролог», «Глава N», «Эпилог»,
  «От автора» (не идёт в рукопись), служебные «Аннотация», «Синопсис». Знаки считаются по вкладкам глав.
  Редактор главы пишет прямо во вкладку; «+ Глава» создаёт новую вкладку.
- **Todoist** (API v1, `https://api.todoist.com/api/v1`), ключ — в Настройках Мастерской:
  - свои задачи: проект «Книги» → раздел = книга; проект «Мастерская» → разделы (в т. ч. «Деньги и реклама» —
    они видны и в «Доходах»). Задачи показываются в Планере, на странице книги; открываются, правятся,
    переносятся перетаскиванием, закрываются — всё синхронно с Todoist;
  - напоминания Мастерской — задачи с меткой `мастерская` (создаёт и закрывает приложение);
  - идеи — задачи с меткой `идея` ⇄ раздел «Идеи».

## 7. Дизайн (то, что владелица ценит больше всего)

- **Минимализм, гармония, единообразие.** Пастельно-розовый (`--accent-2`, `--accent-soft`) и изумрудно-зелёный
  (`--link`, `--good`) — только акценты. Основной текст чёрный (`--text`), второстепенный тёмно-серый (`--text-2`, `--muted`).
  Названия книг — чёрные, не цветные.
- Цвета только через переменные в `:root` (`css/style.css`); есть светлая и тёмная тема — проверять обе.
- **Кнопки одного вида:** главное действие блока — одна розовая кнопка (`primary`); действия с файлами
  (Word, PDF, Текст, Синопсис, Скопировать) — тихие ссылки с иконкой (`button.dl`); иконки — из `js/icons.js`,
  простые линейные (галочка, часики, скачать), без кружков с обводкой и эмодзи.
- Никаких нагромождений плашек: статус — точкой и словом, второстепенное — серым текстом в одну строку.
- Телефон: ширина ~390 px, числа не переносятся, ничего не вылезает за экран, нижнее меню не перекрывает контент.
  Компьютер: левое меню (сворачивается), контент по центру.
- Перед ответом «готово» — посмотреть скриншот на телефоне и компьютере.

## 8. Ключевая логика (чтобы не сломать)

- **Доходы:** продажи из выгрузки Литнета; доход «до вычетов» = роялти; «чистыми» = роялти − комиссии − реклама − налог.
  Налог НПД 4 % по умолчанию с полной цены книг (`taxBase: 'gross'`). Лимит НПД — 2,4 млн в год по базе налога.
- **Цели по месяцам** (Финансы): `buildPlan` + `planOverridesOf(settings)` (путь большой цели, поверх — свои правки).
  Везде, где строится план, использовать `planOverridesOf(s)`, а не `s.planOverrides`.
- **Большая цель:** задаётся «чистыми» в месяц к месяцу; старт пути — свой (например, октябрь 2026 — 50 000 ₽ роялти)
  или по данным. Перевод «чистыми» → роялти — по долям из отчётов (реклама растёт вместе с доходом).
  Год, где база налога превышает лимит НПД, считается как ИП на УСН 6 % или АУСН 8 % (выбор владелицы, ещё не решено).
  Сохранение цели сразу пересчитывает цели по месяцам.
- **Конкурсы:** условия вставляются текстом/ссылкой → `parseContest` сам заполняет поля. Понимает сокращённые
  месяцы Литнета («31 июл. 2026»), не путает правила выкладки с объёмом книги. Если `newOnly`:
  книга «участвует», пока пишется, подать можно **только завершённую** (статус «Завершена») — тогда напоминание
  «Подать» в Планере и кнопка «Отправила» (отдельно по каждой книге). Файлы для конкурса скачиваются с именем по условиям.
  Есть календарь конкурсов на 12 месяцев и вставка целого списка конкурсов.
- **Планер:** дела дня (выкладка глав, цели, конкурсы, Todoist, налог/реклама из «Доходов»); дела и цели
  можно перетащить на другой день недели (у цели день переносится с двойной нормой, есть «Вернуть»).
- **Выкладка глав:** по площадкам, с таймером; события уходят в «Доходы» (`sync.js`).

## 9. Как работать над задачей

1. Понять просьбу по скриншоту/тексту; найти место в коде (`grep` по русскому тексту с экрана — быстрее всего).
2. Сделать минимальную аккуратную правку в стиле соседнего кода (комментарии — по-русски, коротко).
3. Если меняется расчёт — добавить/обновить тест в `tests/`.
4. `npm test`, `node --check` изменённых файлов, проверка в браузере (телефон 390 px и компьютер, без ошибок в консоли).
5. Коммит с понятным русским описанием → push в рабочую ветку → коротко ответить владелице, что поменялось и где смотреть.

## 10. Открытые вопросы и планы

- Выбор режима после НПД (УСН 6 % или АУСН 8 %) — владелица ещё решает; в «Большой цели» есть переключатель.
- Реальный Todoist владелицы проверялся только через заглушки в тестах — при жалобах на синхронизацию смотреть
  `writer/js/todoist.js` (`todoistPlan`, `syncTodoist`, `ideasPlan`).
- Условия конкретных конкурсов приложение разбирает эвристиками: если разбор ошибся — улучшать `parseContest`
  и добавлять случай в `tests/wcalc.test.js`.
