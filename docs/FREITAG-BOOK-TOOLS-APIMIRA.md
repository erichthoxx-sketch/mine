# Freitag AI · проверка главы через BotHub и ApiMira

Текущая рабочая версия описана в [Freitag AI](FREITAG-INFRASTRUCTURE.md). Ниже сохранены сведения о предыдущем этапе подключения.


## BotHub через Anthropic Messages

Для глав с BotHub шлюз выполняет потоковый запрос `POST /api/v2/anthropic/v1/messages`. Уровень рассуждений выбирается в чате, по умолчанию он средний. Инструкция, главы из Мастерской и задание передаются без сокращений. Обычный диалог и ручной Batch используют свои прежние маршруты.

Кнопка проверки соединения выполняет только авторизованный `GET /api/v2/anthropic/v1/models` и чтение списка MCP-инструментов. Наличие модели в списке подтверждает доступ к каталогу, но не подтверждает завершение длинной генерации. После обрыва потоковый путь показывает полученный фрагмент и предупреждение, без повторной отправки или перехода на Batch. [Документация Anthropic-совместимого маршрута BotHub](https://bothub.chat/api/v2/swagger/)

## AITUNNEL с оценкой стоимости

В **Настройки → Модель** выберите **AITUNNEL · Claude Opus 5.5**. Для тестового Worker `freitag-opus-gateway` добавьте Cloudflare Secret `AITUNNEL_API_KEY`. В AITUNNEL задайте этому API-ключу отдельный бюджет. Кнопка **Проверить соединение** выполняет только бесплатные запросы каталога, баланса, бюджета ключа и списка инструментов Мастерской.

Перед отправкой Freitag AI собирает инструкцию, задание и снимок книги, получает бесплатную оценку входных токенов AITUNNEL и прибавляет стоимость выбранного потолка ответа. Если расчёт помещается в доступный остаток, приложение просит подтвердить сумму. При изменении текста, снимка или росте оценки нужно получить её снова. При подтверждении шлюз выполняет один потоковый запрос и показывает фактическое списание, когда провайдер присылает его в потоке. Оценка зависит от тарифа и счётчика токенов. Бюджет ключа контролирует AITUNNEL.

Шлюз использует строки тарифа Amazon Bedrock, передаёт `X-AITunnel-Log: off` и требует маршрутизацию без хранения данных провайдером. Если этот маршрут недоступен, автоматического переключения на другую модель нет. [Лимиты AITUNNEL](https://aitunnel.ru/docs/keys) · [Расход на запрос](https://aitunnel.ru/docs/api/request) · [Политика выбора провайдера](https://aitunnel.ru/docs/provider)

## Отдельный шлюз ApiMira

На рабочем адресе Freitag AI запросы ApiMira идут через `freitag-api-gateway`. Шлюз проверяет вход владельца и читает выбранную книгу из тех же закрытых снимков Мастерской. В рабочем проекте остаются чаты, материалы и память. Шлюз собирается Wrangler из `proxy/freitag-modelproxy-worker.js` с `FREITAG_PROVIDER_GATEWAY=1`, `BOOKS` и `OWNER_UID`. Ключ ApiMira хранится в секрете `APIMIRA_API_KEY` этого Worker.

Бесплатная проверка читает тариф и доступный баланс. В окне «Контекст и цена» Freitag показывает оценку входа и ответа до выбранного лимита. Счётчик токенов ApiMira приблизителен, условия бюджета ключа определяет ApiMira. После подтверждения запрос выполняется один раз. Если оценка выросла или изменился подготовленный запрос, требуется новое подтверждение. Подтверждённый чек сохраняется в чате и разделе «Траты». [Документация ApiMira](https://apimira.com/docs)

## Что происходит при отправке

В проекте можно один раз сохранить авторскую инструкцию. Для следующей главы открой новый чат этой книги, вставь привычное задание и выбери провайдера. Для связанного проекта Freitag AI сначала бесплатно читает канон и две последние главы из последнего синхронизированного снимка Мастерской. Если рукопись в Google Docs изменилась после синхронизации, в проекте есть кнопка «Обновить Google Docs».

Потоковая генерация главы использует один запрос к выбранной модели. Текст, уже полностью включенный в задание, второй раз из соответствующей главы не добавляется. Для внешних API доступны общие лимиты ответа: 4 500, 9 000, 14 000, 20 000 и 32 000 токенов. Входные сообщения ограничены 130 000 знаков на сообщение, 180 000 в сумме и 340 000 байт на запрос браузера. Для канона и двух глав выделено до 180 000 знаков. Если материал не помещается или снимок меняется во время чтения, шлюз останавливается до генерации.

Пока идет ответ, первые строки и последующие фрагменты сохраняются в чате этого браузера. При обрыве или достижении лимита приложение помечает результат как неполный. Повтор и переключение на другого провайдера требуют отдельного действия автора. После закрытия вкладки доступен последний записанный фрагмент. Потоковая задача в браузере не возобновляется.

В меню чата **Ещё → Контекст и цена** можно бесплатно посмотреть главы, сцены и выбранные материалы. Для BotHub и ModelProxy показывается оценка по публичному тарифу и приблизительному числу токенов. ApiMira и AITUNNEL предоставляют счётчик входа и сведения о балансе. После запроса видны переданные провайдером токены и подтверждённая сумма, если интеграция получила её.

**Ещё → Написать в фоне** сохраняет подтверждённое задание в закрытом Durable Object с SQLite. Задание запускается по alarm и сохраняет текст по мере получения. Номер задания предотвращает повторную отправку при сетевом сбое. После перезагрузки или входа с другого устройства результат можно открыть в **Фоновых главах** и сохранить в чате. Окно доступа к фоновому результату составляет 30 дней.

Для каждого шлюза нужна привязка Durable Object `CHAPTER_JOBS` к классу `ChapterJobs` и одноразовая миграция SQLite `freitag-chapters-v1`. При обновлении сохраняются прежние ключи, режим шлюза и привязка `BOOKS`. Работающий потоковый маршрут использует тот же код генерации. Внешние маршруты платной модели проверяют Firebase владельца до доступа к очереди. Объект получает подготовленный запрос без токена браузера и удаляет запрос перед обращением к модели.

## Что установлено по задаче № 23

| Проверка | Результат и его значение |
| --- | --- |
| BotHub, обычный запрос | По двум попыткам, описанным в задаче, BotHub вернул HTTP 524 до появления текста. Freitag AI преобразовывал этот ответ в 502. Шлюз запрашивал поток, а Pages передавал его по мере поступления. Определить по этим ответам, сколько времени заняла работа модели и были ли списания, невозможно. |
| BotHub, Batch | По истории задачи файл был загружен, а создание задачи получило HTTP 403 без идентификатора. Формат файла, адрес запуска, окно 24 часа и выбор модели из каталога сверены с документацией BotHub. Бесплатный каталог подтверждает наличие модели. Разрешение на запуск требует отдельного подтверждения провайдера. Причина прежнего 403 неизвестна. |
| ApiMira | Бесплатный запрос без ключа вернул модель в каталоге. Запрос баланса без ключа вернул HTTP 401. Поэтому для проверки ключа требуется отдельный ответ от аккаунта. По документации бронь учитывает входной текст и выбранный максимум выхода. Доступного остатка в долларах самого по себе недостаточно для обещания успешной генерации. |
| Доставка текста | Старый шлюз ограничивал всю потоковую главу таймером на 160 или 300 секунд. Активный поток мог оборваться. Этот таймер убран. Тайм-ауты на стороне провайдеров продолжают действовать. В частности, ApiMira указывает 120 секунд до начала ответа и 240 секунд тишины в процессе. |
| Опубликованная версия | Во время аудита обращения из среды разработки к тестовому Pages и самому Worker получили страницу Cloudflare 403/1010. Исходники в GitHub, права аккаунта и запущенную версию Worker нужно проверять по отдельности. Подлинная оплаченная глава в рамках аудита не запускалась. |

При отказе в журнале чата видны этап, HTTP-статус провайдера и, когда они доступны в безопасном формате, код ошибки и идентификатор запроса. По ним можно сверить конкретную попытку с поддержкой и историей расходов. Исходный ответ с потенциальными фрагментами рукописи в сообщение об ошибке не копируется.

## Публикация и бесплатная проверка

1. Дождаться проверки PR. Для тестового проекта Cloudflare Pages `freitag-ai-test` нужна Preview-сборка с тем же коммитом. Локальные чаты привязаны к адресу сайта, поэтому другая Preview-ветка может открыться с пустой историей.
2. В Cloudflare открыть **отдельный** Worker `freitag-opus-gateway`, сохранить номер действующей версии для отката и опубликовать в нем содержимое `proxy/freitag-modelproxy-worker.js` из проверенного коммита. Коммит и публикация Pages сами этот Worker не обновляют.
3. У рабочего Worker проверить наличие `OWNER_UID`, `BOTHUB_API_KEY`, `MCP_READ_KEY` и `BOOKS_MCP_URL` с адресом действующего MCP Мастерской. Существующая привязка KV `BOOKS` используется для ручного обновления снимка и сохранения принятого номера Batch. Секрет ApiMira настраивается в отдельном шлюзе.
4. В настройках Preview проекта Pages проверить сервисную привязку `FREITAG_GATEWAY` к этому Worker. Если привязка менялась, повторить сборку Preview. На адресе Preview открыть `/api/freitag/health`. Версию из этого исправления отличает `chapterProtocol: 2`. Флаги `apimiraConfigured`, `bothubConfigured` и `mcpConfigured` показывают наличие настроек.
5. Войти в тестовую Freitag AI, выбрать ApiMira и нажать **«Проверить соединение»**. Проверка читает каталог, доступный баланс и список инструментов Мастерской. Для BotHub бесплатная проверка читает каталог. Кнопка **«Проверить Batch бесплатно»** тоже не загружает файл и не создает задачу.
6. Для реальной приемки нужно отдельное разрешение на **одну платную главу**. Результат подтверждается, когда окончание главы видно в чате, после перезагрузки текст доступен полностью и списание сверено с историей провайдера. При 524 или отсутствии номера Batch сначала проверить историю операции.
