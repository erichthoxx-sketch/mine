# Freitag AI + BotHub — подключение

**Где:** «Мастерская» → Нейросети → **Freitag AI ↗**, либо `/ai/`. Это отдельный литературный чат, не замена редактору рукописей. Изменения книг и глав не разрешены.

## Архитектура

`ai/app.js` → HTTPS Cloudflare Pages `/api/freitag/*` → Service binding `FREITAG_GATEWAY` → Worker `proxy/freitag-modelproxy-worker.js` → BotHub API.

Перед **каждым платным сообщением для связанной книги** Freitag AI заново читает книгу из Firebase и главы прямо из Google Docs, затем отправляет свежий снимок в KV `BOOKS` через защищенный `POST /refresh-book`. Вслед за ним платная генерация требует **совпадающей версии снимка** — если KV еще отдает старую версию, запрос блокируется. Действующий MCP Worker и ключи «Мастерской» не меняются. Доступ к генерации и снимку требует подтвержденный Firebase ID token владельца (`OWNER_UID`).

## Настройка (делается владельцем один раз)

1. В BotHub → «Для разработчиков» создай API-ключ. **Не вставляй его в браузер, чат, GitHub или JS.**
2. В Cloudflare Worker `freitag-opus-gateway` укажи **Secret** `BOTHUB_API_KEY`. Сохрани существующие `OWNER_UID` и KV binding `BOOKS`. `MODELPROXY_API_KEY` для BotHub не нужен.
3. Опубликуй новую версию Worker из `proxy/freitag-modelproxy-worker.js` с **KV binding `BOOKS` к тому же namespace, что у MCP-Worker «Мастерской»**. Для тестовой Pages `freitag-ai-test` оставь binding `FREITAG_GATEWAY` → `freitag-opus-gateway`; Pages Function `functions/api/freitag/[route].js` маршрутизирует вызовы.
4. В Freitag AI войди под тем же Firebase аккаунтом, свяжи книгу с «Мастерской» и разреши Google Drive, если браузер запросит доступ. Перед каждым сообщением Freitag AI сам загружает актуальный Google Документ — кнопка «Обновить весь контекст» для этой работы больше не требуется.
5. Freitag AI → Настройки → **BotHub · Claude**. Выбери **Sonnet 5.5** (по умолчанию) либо **Opus 5.5**, нажми «Проверить соединение». Проверка читает `GET /v1/models`, не запускает платную генерацию. Ключ и доступность модели проверяются сервером.
6. В чате выбери книгу и отправь короткий запрос. На первом платном запросе за сессию появится подтверждение передачи выбранной книги стороннему провайдеру. **Этот запрос уже платный**. Последующие сообщения автоматически читают свежие материалы. Проверь списание в кабинете BotHub.

## Модели и защита

- Разрешены только `claude-sonnet-5.5` и `claude-opus-5.5`; сервер не принимает произвольный URL или имя модели от браузера.
- Адрес BotHub: `https://openai.bothub.chat/v1`; только Worker отправляет туда авторизованные запросы.
- `GET /health` проверяет конфигурацию, но не действительность ключа. `GET /preflight?model=…` требует Firebase-аутентификацию и проверяет каталог доступных моделей без генерации.
- Рукописи и сообщения при платной генерации передаются третьей стороне — BotHub. Не пересылай неопубликованный текст без согласия на это.
- Перед платной генерацией для связанной книги обязательны успешное чтение Google Docs, синхронизация в KV и совпадение версии. Неудача на любом этапе останавливает запрос до оплаты. История чатов остается локально в IndexedDB.
- Если доступен только BotHub, ModelProxy можно оставить не настроенным, Ollama продолжит работать отдельно.

## Для следующего разработчика / Codex

Проверяй прежде всего `proxy/freitag-modelproxy-worker.js`, `ai/app.js`, `functions/api/freitag/[route].js` и `tests/freitag-modelproxy.test.js`. Не меняй `proxy/books-mcp-worker.js`, не записывай ничего в рукописи и не публикуй рабочий Worker до теста в отдельной среде.

Тесты: `npm test` (Node.js 22). API-ключ, Cloudflare binding и реальную платную генерацию тестовый набор не эмулирует полностью; их нужно проверить после развертывания.

## Ограничения

- Google OAuth в браузере живет ограниченное время. Если сессия истекла, Google может попросить повторно подтвердить вход при нажатии «Отправить». Без участия пользователя обновление закрытого Google Документа недоступно.
- Когда Freitag AI закрыт и пользователь только работает в Google Docs, сама по себе синхронизация в Cloudflare не запускается. **Автоматическая актуализация происходит при отправке сообщения через Freitag AI**.
- Cloudflare KV распространяет изменения между регионами не мгновенно. Запрос с несовпадающей версией блокируется и не должен уходить в BotHub.
- Существующий Claude MCP и Google Drive подключены к прежнему Worker; они получают изменения через существующую синхронизацию Мастерской и новый автоснимок Freitag AI.
- В ChatGPT текущая форма создания пользовательского MCP не может принять наш `x-api-key` напрямую: она поддерживает OAuth или no-auth. Не отключай защиту MCP и не публикуй ключ в URL. Нужен совместимый OAuth bridge и доступность пользовательского MCP на аккаунте ChatGPT.
