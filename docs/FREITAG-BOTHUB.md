# Freitag AI + BotHub — подключение

**Где:** «Мастерская» → Нейросети → **Freitag AI ↗**, либо `/ai/`. Это отдельный литературный чат, не замена редактору рукописей. Изменения книг и глав не разрешены.

## Архитектура

`ai/app.js` → HTTPS Cloudflare Pages `/api/freitag/*` → Service binding `FREITAG_GATEWAY` → Worker `proxy/freitag-modelproxy-worker.js` → BotHub API.

В том же Worker читается снимок книги из KV `BOOKS` (который заполняет существующая «Мастерская»). Действующий MCP Worker и ключи «Мастерской» не меняются. Доступ к генерации и снимку требует подтвержденный Firebase ID token владельца (`OWNER_UID`).

## Настройка (делается владельцем один раз)

1. В BotHub → «Для разработчиков» создай API-ключ. **Не вставляй его в браузер, чат, GitHub или JS.**
2. В Cloudflare Worker `freitag-opus-gateway` укажи **Secret** `BOTHUB_API_KEY`. Сохрани существующие `OWNER_UID` и KV binding `BOOKS`. `MODELPROXY_API_KEY` для BotHub не нужен.
3. Опубликуй новую версию Worker из `proxy/freitag-modelproxy-worker.js`. Для тестовой Pages `freitag-ai-test` оставь binding `FREITAG_GATEWAY` → `freitag-opus-gateway`; Pages Function `functions/api/freitag/[route].js` маршрутизирует вызовы.
4. В «Мастерской» нажми «Обновить весь контекст» и проверь дату синхронизации главы. В Freitag AI войди под тем же Firebase аккаунтом, свяжи книгу с «Мастерской».
5. Freitag AI → Настройки → **BotHub · Claude**. Выбери **Sonnet 5.5** (по умолчанию) либо **Opus 5.5**, нажми «Проверить соединение». Проверка читает `GET /v1/models`, не запускает платную генерацию. Ключ и доступность модели проверяются сервером.
6. В чате выбери книгу и отправь короткий запрос. Перед первой отправкой снимка покажется подтверждение, какие главы будут переданы. **Этот запрос уже платный**. Проверь списание в кабинете BotHub.

## Модели и защита

- Разрешены только `claude-sonnet-5.5` и `claude-opus-5.5`; сервер не принимает произвольный URL или имя модели от браузера.
- Адрес BotHub: `https://openai.bothub.chat/v1`; только Worker отправляет туда авторизованные запросы.
- `GET /health` проверяет конфигурацию, но не действительность ключа. `GET /preflight?model=…` требует Firebase-аутентификацию и проверяет каталог доступных моделей без генерации.
- Рукописи и сообщения при платной генерации передаются третьей стороне — BotHub. Не пересылай неопубликованный текст без согласия на это.
- Снимок из KV должен быть свежим (по умолчанию не старше семи суток); отсутствие или устаревание останавливает платный вызов. История чатов остается локально в IndexedDB.
- Если доступен только BotHub, ModelProxy можно оставить не настроенным, Ollama продолжит работать отдельно.

## Для следующего разработчика / Codex

Проверяй прежде всего `proxy/freitag-modelproxy-worker.js`, `ai/app.js`, `functions/api/freitag/[route].js` и `tests/freitag-modelproxy.test.js`. Не меняй `proxy/books-mcp-worker.js`, не записывай ничего в рукописи и не публикуй рабочий Worker до теста в отдельной среде.

Тесты: `npm test` (Node.js 22). API-ключ, Cloudflare binding и реальную платную генерацию тестовый набор не эмулирует полностью; их нужно проверить после развертывания.
