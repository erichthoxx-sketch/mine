# Freitag AI

[Рабочая Freitag AI](https://codex-freitag-aitunnel.freitag-ai-test.pages.dev/ai/)

## Что сохраняется

Код Freitag, тесты и этот документ находятся в ветках `codex/freitag-workspace` и `codex/freitag-aitunnel` репозитория `erichthoxx-sketch/mine`. Рабочий адрес собирается из второй ветки. Текущие изменения видны в истории Git. Для работы с самим романом владелица выдаёт доступ к конкретному проекту в Freitag.

| Данные | Хранилище | Доступ |
| --- | --- | --- |
| Авторская рукопись | Google Docs и подключённый снимок «Мастерской» в Cloudflare KV | Источники Freitag читают снимок с датой обновления |
| Маркетинг, продажи, прочтения | Закрытые снимки приложений в KV | По задаче, периоду и книге |
| Реклама, Метрика, когорты | Существующий MCP «Мастерской», разрешённые отчёты Яндекса и снимки | Только чтение |
| Чаты, решения, материалы, настройки, расходы | IndexedDB рабочего адреса | В Firebase можно включить личную автокопию в настройках Freitag. Она хранит две версии |
| Проект, открытый другому ИИ | Отдельный SQLite Durable Object в аккаунте владелицы | Ключ на чтение одного проекта. Отзыв удаляет его копию и делает ключ недействительным |

В памяти проекта Freitag учитывает решения автора, материалы и подходящие реплики. Из других чатов выбираются реплики автора и одобренные ответы. «Не то» убирает вариант из дальнейшего подбора. Открыть список фактически выбранных источников можно под новым ответом в «Состав запроса».

## Как работает запрос

`ai/source-plan.js` определяет необходимые источники по текущей задаче. Короткое уточнение периода может наследовать тему предыдущей реплики. Для вопроса о продажах Freitag суммирует все подходящие строки снимка до сокращения ответа. Для вопроса о сцене поиск просматривает главы и возвращает выдержки с указанием места. Для главы в режиме «По заданию» берутся канон, две предыдущие главы и связанные сцены по сюжетным указаниям автора. Если автор указал номер существующей главы, подбор учитывает её место в рукописи. В режиме «Вся рукопись» оба шлюза читают целиком один и тот же закрытый снимок книги. Для BotHub по умолчанию действует маршрут 23 ноября: канон, две последние главы и короткие выписки. Выбор полной рукописи для BotHub действует на одну подтверждённую отправку. Остальные провайдеры используют выбор проекта. Окно оценки показывает состав перед отправкой. Если глава целиком вставлена в задание, она передаётся один раз. Финансовая статистика в художественной задаче не подгружается по случайному упоминанию денег в тексте.

Обычный интерфейс вызывает защищённый `POST /context` на основном шлюзе. В `proxy/freitag-sources.js` определены доступные операции и предельный объём результата. Если требуемый источник недоступен, интерфейс покажет ошибку до генерации. В «Контекст и цена» видны источники. Полученная выборка остаётся в памяти запроса и используется при оценке и отправке. Дополнительная платная генерация для выбора инструментов не требуется.

Основной шлюз BotHub доступен через Pages `/api/freitag`. ApiMira и ModelProxy используют отдельный `freitag-api-gateway`. Рабочие ключи выдаёт Cloudflare через секреты окружения. Основной шлюз проверяет Firebase ID token и UID владельца. Формат ответа общего коннектора одинаков для провайдеров. Исторические клиенты основного шлюза могут пользоваться прежним ограниченным циклом инструментов. Локальная Ollama может читать выборку после входа в Мастерскую при подключении к localhost.

В `ai/chapter-limits.js` заданы уровни рассуждений. BotHub принимает нативное поле Anthropic `output_config.effort` и адаптивное мышление. ApiMira получает `reasoning_effort` в совместимом интерфейсе. Модель и провайдер определяют фактическую глубину рассуждений. Платный тест требует отдельного согласия владелицы.

## Передача проекта

В карточке книги открой **Передать проект → Включить доступ на чтение**. Внешнему MCP-клиенту, который поддерживает Streamable HTTP с заголовком авторизации, нужны показанные адрес и значение заголовка `Authorization`. Ключ показывается один раз. Обычный новый диалог или переключение модели внутри Freitag используют уже имеющийся доступ. Для приложений с поддержкой только файлов та же карточка позволяет скачать проект в Markdown.

Клиент начинает с `list_documents` и `read_document` с идентификатором `project`. Решения, инструкции, включённые материалы, образцы и чаты представлены разными записями. `search_project` возвращает выдержки, `read_document` позволяет дочитать запись частями. Если книга связана с Мастерской, доступны `get_book_context`, `list_chapters`, `search_book` и `read_chapter` этой рукописи. Светить ключ в URL или GitHub не требуется. Расходы, приватные настройки и чужие проекты в пакет не входят.

После выдачи доступа изменения из этого браузера обновляют пакет при открытой Freitag. При расхождении версий двух устройств автоматическое обновление приостанавливается. Владелица выбирает нужную версию в карточке проекта. Обновление рукописи поступает через отдельную синхронизацию Мастерской. Реализация находится в `ai/handoff.js` и `proxy/freitag-project-access.js`.

## Учёт расходов

Раздел «Траты» автоматически читает `GET /billing-history` обоих шлюзов. Для ApiMira источником служит журнал операций выбранной модели через `/v1/account/usage`. Для BotHub это API-транзакции с ключом разработчика. В ответ интерфейсу попадают только номера, время, аккаунтные единицы суммы и доступные счётчики. Сопоставление с чатами опирается на точный ID операции или запроса. Непривязанные операции видны отдельно, валюты и Caps сохраняются раздельно. Сведения за последние 90 дней подгружаются страницами, известные операции сохраняются в истории. Оценка по токенам помечается знаком «≈».

## Проверка и выпуск

- Запустить `npm test`. Тесты внешних источников и моделей используют фиктивные данные.
- Собрать рабочий пакет командой `bash scripts/build-apps.sh vtest /tmp/freitag-build`. Для браузерной проверки использовать `FREITAG_TEST_BUILD=/tmp/freitag-build node scripts/freitag-chapter-smoke.mjs` с установленными Playwright и Chromium. Проверить оба размера экрана.
- Перед обновлением двух шлюзов сверить активные версии и bindings. Обоим нужны прежние `BOOKS`, `CHAPTER_JOBS` и `OWNER_UID`. Оставить существующие секреты и маршруты. Не обновлять Worker Мастерской или Директа ради выпуска Freitag.
- После выпуска проверить содержимое версионированных модулей с рабочего адреса, `/health` обоих шлюзов и отказ при доступе к личным маршрутам без авторизации.
