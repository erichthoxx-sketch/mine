# Freitag AI → Claude Opus 5.5 через Polza.ai (пилот)

**Статус:** реализация подготовлена в изолированной GitHub-ветке `feature/freitag-ai-polza-opus`. Она **не развернута** и не меняет работающие «Мастерскую», Freitag AI, «Доходы» или действующий Books MCP Worker.

## Что реализовано

- Переключение Freitag AI: **Ollama** (как раньше) / **Claude Opus 5.5 через Polza.ai**.
- Передача запросов только через отдельный Cloudflare Worker; API-ключ не попадает в браузер, Firebase или GitHub.
- Worker принимает только подписанный Firebase ID token **конкретной владелицы** (`OWNER_UID`), проверяя Google JWKS, и только после этого обращается к платному API.
- При выборе книги Worker **автоматически** запрашивает у существующего MCP «Мастерской» канон, порядок глав и тексты последних двух глав. Полная рукопись остаётся доступной в MCP, но в первом пилоте не пересылается целиком — иначе резко растет цена и риск перепутать версии.
- Для литературного задания добавляются авторские инструкции и отобранные примеры из памяти Freitag AI.
- Поддерживаются потоковые ответы (SSE), остановка ответа и сохранение переписки в браузере как прежде.
- Если снимок книги в MCP старше **7 суток**, запрос не отправляется в Polza, пока ты не обновишь его в «Мастерской». Затраты на такой неудачный запрос должны быть нулевыми.
- Первый тест делай **без выбранного романа**, в режиме «Диалог»: так не понадобится MCP, а ответ будет коротким.

## Рекомендуемый способ подключения книг: та же KV namespace (без старого MCP-ключа)

Если прежний `MCP_READ_KEY` недоступен, **не сбрасывай и не заменяй его**. Новый gateway умеет читать снимки книг напрямую из той же Cloudflare Workers KV namespace, что и действующий `masterskaya-ai`.

1. Открой в Cloudflare существующий `masterskaya-ai` → **Settings → Bindings**. Найди binding `BOOKS` типа **KV namespace** и запомни, к какой namespace он привязан. **Ничего там не меняй.**
2. Открой **новый** `freitag-opus-gateway` → **Settings → Bindings → Add binding → KV namespace**.
3. В поле **Variable name** укажи точно `BOOKS`, в **KV namespace** выбери **ту же самую** namespace из шага 1. Сохрани.
4. В редакторе **нового** Worker замени код обновленным `proxy/freitag-polza-worker.js` из ветки `feature/freitag-ai-polza-opus` и нажми **Deploy**.
5. Проверь URL `/health`: `booksConnected:true` означает наличие KV binding. Само чтение снимков проверяется отдельно авторизованным запросом с выбранной книгой.
6. Уже заданная переменная `BOOKS_MCP_URL` не мешает: при наличии KV binding новый шлюз использует его, а прежний Worker не трогает.

⚠️ KV namespace — общее хранилище, **не создавай новую пустую namespace**. У нашего нового Worker в коде используются только операции `get`, изменений в книгах он не делает. Доступ к платной генерации по-прежнему требует проверенный Firebase ID token владелицы.

## Развертывание — строго отдельный Worker

1. В Cloudflare открой **Workers & Pages → Create → Worker**, создай отдельный Worker с именем вроде `freitag-opus-gateway`. **Не изменяй** работающий Worker «Мастерской» или «Директа».
2. В редактор нового Worker вставь код из `proxy/freitag-polza-worker.js`, затем нажми Deploy.
3. В **Settings → Variables and Secrets** нового Worker добавь **секреты**:
   - `POLZA_API_KEY`: уже сохраненный ключ `pza_...` (никому не отправляй);
   - `OWNER_UID`: UID твоего пользователя в Firebase Authentication (можно получить в консоли Firebase → Authentication → Users). Это **не** email и не API-ключ;
   - `MCP_READ_KEY`: **необязателен**, если подключен тот же KV namespace через binding `BOOKS`. Существующий ключ не сбрасывай.
4. **Рекомендуется:** настрой binding `BOOKS` по инструкции выше. Как запасной вариант можно добавить строковую переменную `BOOKS_MCP_URL`: **полный адрес** твоего существующего MCP, включая `/mcp`. В таком варианте нужен и `MCP_READ_KEY`. Смотри в «Мастерская → Настройки → Нейросети». Адрес не должен указывать на Polza, это адрес твоего Worker для чтения книг. Неизвестный адрес не угадывай.
5. Открой `https://<имя-твоего-worker>.workers.dev/health`. Ожидаемый ответ содержит `ok:true`, `configured:true`, `booksConnected:true`. Эта проверка не тратит баланс Polza.
6. После проверки **не сливай ветку автоматически**. Лишь когда готова включить обновленный Freitag AI, нужно отдельно протестировать его на изолированном адресе или предварительном развертывании. Публикация основной ветки приведет к обновлению рабочего приложения.

## После безопасной публикации пилота

Открой Freitag AI → **Настройки**:
- Провайдер: **Claude Opus 5.5 через Polza**.
- Адрес шлюза: `https://<имя-твоего-worker>.workers.dev` (без `/health` или `/chat`).
- Сохрани и нажми **Проверить соединение**.
- В **Проекты** войди в прежний аккаунт «Мастерской», обнови связанную книгу.
- Сначала в новом чате без проекта напиши «Привет» в режиме **Диалог** (до 1800 выходных токенов).
- Затем тестируй «Написать сцену» с выбранной книгой: до 10 000 выходных токенов, стоимость может быть значительно выше.

## Ограничения

1. Код и парсер SSE проверены синтаксически. **Реальный вызов Opus не выполнен**: ключ хранится только у владелицы.
2. Текущая версия **не выполняет многошаговый цикл планирования → написания → редактуры**, не индексирует все главы и не гарантирует стиль на уровне издательства. Это будет следующий этап после первого успешного платного ответа.
3. Книги в MCP — **снимки**, которые должны синхронизироваться с «Мастерской» после изменений. Повторное обновление только проекта Freitag AI не гарантирует актуальность текста глав в MCP.
4. Логирование в Polza можно выключить в настройках API-ключа, но запросы всё равно обрабатываются посредником и провайдером модели.
5. **Дневной лимит 300 ₽ в Polza — ограничение затрат ключа, не фиксированная цена главы.** Для теста достаточно существующих 100 ₽.

## Адреса сервиса

- Polza OpenAI-compatible API: `https://polza.ai/api/v1/chat/completions`
- Модель: `anthropic/claude-opus-5.5`
- Новое приложение вызывает только личный Worker: `GET /health` и `POST /chat`.

## Правило отката

Пока не было слияния в основную ветку и деплоя отдельного Worker, рабочие сервисы не меняются. Даже после создания Worker ключ можно отозвать в кабинете Polza или удалить из секретов нового Worker. Не меняй и не удаляй действующий Books MCP Worker.
