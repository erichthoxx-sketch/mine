# Freitag AI — рабочее пространство автора (версия Preview)

Текущая рабочая версия описана в [Freitag AI](FREITAG-INFRASTRUCTURE.md). Ниже сохранены сведения о предыдущем этапе подключения.


Статус: отдельная ветка, не заменяет действующий Cloudflare Worker и production-версию Freitag AI.

## Как должна работать новая версия

- Раздел «Книги»: создание проекта книги из Мастерской либо вручную; экран проекта содержит редактируемые **инструкции автора**, дополнения к канону, голосу и текущей сцене, материалы и историю чатов.
- Раздел «Чаты»: широкий, адаптивный чат с читаемыми Markdown-абзацами, заголовками и списками. Модель BotHub Opus/Sonnet или резерв ApiMira переключается прямо у поля отправки, набранный текст сохраняется.
- **Никаких навязанных промптов для Opus:** модель получает только общие инструкции автора (если заполнены), инструкции выбранного проекта, явно добавленные автором дополнения и одобренные примеры. На стороне сервера — только нейтральные правила обращения к read-only инструментам MCP.
- **Google OAuth не появляется при каждой отправке.** Перед запросом проверяется сохраняемая Firebase-сессия владельца (без всплывающего окна Google), затем Opus сам запрашивает нужные источники через существующий MCP-сервер Мастерской. Если пользователь еще не вошел во Freitag AI через Firebase, потребуется один вход.
- **Свежесть источников — отдельный вопрос.** Автоматически читается последний доступный снимок на MCP. Чтобы перенести совсем новые изменения Google Docs до того, как их синхронизировала Мастерская, в проекте есть явная кнопка «Обновить Google Docs». Она открывает обычный Google OAuth, если истек токен или адрес еще не разрешен в OAuth-клиенте. Никаких автоматических обещаний о реальном времени для Google Docs нет.

## Безопасность и данные

- Исходные MCP и Google Docs не менялись.
- Секреты остаются в Cloudflare Worker. Браузеру передается только кратковременный Firebase ID-token пользователя.
- Existing Projects, drafts, notes and chats are stored in IndexedDB **на конкретном домене**. Переход на новый Preview origin не переносит старые чаты автоматически. Чтобы перенести старые, на старом адресе используй Настройки → Экспорт JSON, а на новом — Настройки → Импорт JSON.
- Для долговременного пользования после приемки интерфейса лучше разместить его по стабильному адресу, а не постоянно создавать Preview с новым hostname. В настройках уже предусмотрено создание облачной копии проектов/инструкций через Firebase (по кнопке), но чаты пока локальные.
- Никакой новой платной генерации от CI и сборки не выполняется.

## Порядок теста

1. **Не публиковать в Production до проверки.** [Preview ветки](https://feature-freitag-ai-project-w.freitag-ai-test.pages.dev/ai/) открывает обновленный интерфейс.
2. Обновить только \`freitag-opus-gateway\` из этой ветки (\`proxy/freitag-modelproxy-worker.js\`), предварительно убедившись, что предыдущий Deploy доступен для отката. Новый Worker допускает обращения к выбранной книге без обязательного \`sourceRevision\`; старый Worker их отклоняет.
3. Открой проект связанной книги, внеси свои инструкции. Проверь «Книги», «Чаты» и Markdown на длинном ответе.
4. В диалоге задай конкретный проверочный вопрос по старой главе. MCP читается через \`tools/call\` без всплывающего Google OAuth. **Это платная генерация у BotHub**, в которой может быть несколько вызовов модели.
5. Если нужно проверить совсем новые правки Google Docs, нажми одно явное «Обновить Google Docs» в проекте. В тестовой ветке для OAuth может потребоваться добавить ее origin в Google Cloud Console.
6. Только после приемки внешнего вида и генерации переносить интерфейс на стабильный адрес.

## Известные ограничения

- Чаты IndexedDB привязаны к origin, их облачная автоматическая синхронизация еще не готова.
- Tool calling в BotHub/ApiMira сейчас выполняется через непотоковый OpenAI-compatible API. Во время работы с длинной сценой пользователь видит ожидание, а финальный ответ появляется после завершения; нужно отдельно проверить реальные задержки, стоимость и устойчивость.
- При выборе «Написать сцену» сейчас ограничение ответа на сервере 4500 токенов; полноценная глава может потребовать продолжения. Увеличивать лимит без замера списаний не следует.
