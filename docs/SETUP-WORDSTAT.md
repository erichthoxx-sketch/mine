# Wordstat в «Директе» — платные запросы выключены по умолчанию

**Безопасность:** API-ключ Yandex Cloud не вводится в браузере, не сохраняется в Firebase и никогда не публикуется в GitHub. Только Cloudflare Worker Secrets. Не присылайте ключ в чате.

## Что уже есть

- «Мастерская» → карточка книги → 1–2 жанра из справочника Литнета + до 20 тегов.
- «Директ» → «Ключи» и «Конкурентная разведка» берут эти поля из общего `w_books`. «Легенда» для жанров и тегов не используется: единый источник — карточка «О книге».
- Wordstat `GetTop` — только по кнопке, с явным подтверждением **для одной фразы**. Ни автоматических ночных обходов, ни изменения живых объявлений.
- Код защищенного API находится в `proxy/direct-worker.js` (версия 5) и по умолчанию выключен.

## Подключение

1. [Yandex Cloud](https://console.yandex.cloud/) → создай/выбери каталог в облаке и подключи платежный аккаунт (не путать с обычным доступом к API Директа).
2. Создай сервисный аккаунт, выдай в нужном каталоге роль **`search-api.webSearch.user`**, затем создай API-ключ с областью **`yc.search-api.execute`**. [Официальная инструкция GetTop](https://aistudio.yandex.ru/ru/docs/search-api/operations/wordstat-gettop).
3. В Cloudflare → **Workers & Pages** → Worker `direct` → **Settings → Variables and Secrets**:
   - `WORDSTAT_API_KEY` — секрет из Yandex Cloud (тип Secret).
   - `WORDSTAT_FOLDER_ID` — ID каталога Yandex Cloud (Text/Secret).
   - `WORDSTAT_OWNER_EMAIL` — электронная почта, которой ты входишь в **Мастерскую/Директ** (Text/Secret).
   - `FIREBASE_PROJECT_ID` — projectId из Firebase, используемого твоим приложением (Text/Secret).
   - `WORDSTAT_ENABLED` — сначала `false`; `true` только после проверки всех параметров.
4. Cloudflare → **KV** → создать namespace для счетчика. Привязать в Worker к имени `WORDSTAT_COUNTER`. Если хранилища или любого секрета нет, Worker не выполнит платный запрос.
5. В «Директе» → «Настройки» обновить Worker (код `proxy/direct-worker.js`), развернуть (Deploy), проверить `/version` = `5`. Только после этого включить `WORDSTAT_ENABLED=true`.
6. В Yandex Cloud Billing отдельно установи **уведомление** о расходах 50 ₽ и проверь доступные бюджетные ограничения. Контроль KV на стороне Worker **ориентировочный**, не является юридически/технически строгим лимитом: при одновременных вызовах счетчик KV может обновляться с задержкой. Поэтому программа не запускает запросы сама; один подтвержденный клик = максимум один запрос к методу GetTop.
7. В «Директе» → «Ключи» выбрать книгу, фразу и подтвердить **«Подобрать через Wordstat»**.

## Стоимость и границы

По тарифам, объявленным Yandex Cloud на октябрь 2026: `GetTop` — 20 ₽ за 1000 запросов (**0,02 ₽ за вызов**), `GetDynamics` — 0,02 ₽, `GetRegionsDistribution` — 0,05 ₽. Тарифы могут меняться, дополнительные услуги облака оплачиваются отдельно. URL, счетчик и источник цены см.: https://yandex.cloud/ru/blog/digest-april-2026 .

В первой версии реализован **только GetTop**: популярные запросы и ассоциации по одной фразе. Диапазон Wordstat — последние 30 дней; число результатов ограничено 100. Общие расходы облака и любые другие запросы к Yandex Cloud не контролируются этим Worker. Счетчик Wordstat записывает одну единицу до запроса (не удачные ответы также резервируются ради предосторожности).

## Проверки безопасности

- Origin ограничен сайтом приложения или localhost при разработке, но **это не аутентификация**.
- Worker проверяет криптографическую подпись Firebase JWT, его issuer, audience, срок, идентификатор и совпадение email с `WORDSTAT_OWNER_EMAIL`.
- Ключ хранится в Cloudflare Secret и только Worker передает его Яндексу.
- Без `WORDSTAT_ENABLED=true`, проекта Firebase, KV и настроенных секретов Wordstat закрыт.
- Нет автоматической генерации платных запросов и изменения ставок, бюджетов, минус-фраз или объявлений.

### Если очень нужен гарантированный потолок

Для строгого лимита с транзакционным списанием вместо KV понадобится Cloudflare Durable Object/D1 со счетчиком в транзакции и/или соответствующая блокировка расходов непосредственно в Yandex Cloud. Пока строгого финансового стопа нет — не включать автоматические платные обращения.
